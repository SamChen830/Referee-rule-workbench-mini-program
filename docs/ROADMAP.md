### 🟡 v1.0.3 — 正文"句中误换行"重排清洗（当前轮次）
**目标**：修复 `rule-detail.js:22` 与 `mech-detail.js:30` 用 `split('\n')` 分段导致的"句中误换行 / 断词跨段"。

**根因**：PDF 抽取把每一物理行都写成字面 `\n`，渲染层把它当作段落分隔 → 完整句子被拆成多段（如 `25.1.1 …所述的⏎限制`）。

- [x] `data/rules.js`：50/50 条重排，仅保留"结构起始"换行（条款号 `25.1`/`25.1.1`、`·`、`——`），段落 `857 → 807`，结构异常 0
- [x] `data/mechanics.js`：134 项 72 项重排；散文+列表感知算法（仅当上段以 `。！？：` 或 `——短关键词` 结尾才另起），段落 `920`，结构异常 0
- [x] 保留合法 0 号球衣手势（`示0号`，2.24 条），未误删数字
- [x] 同源 PDF 连字符伪影清除（控-制→控制、队-员→队员、侧-执→侧执、判-做→判做、转-第→转第、上-获→上获、最-要→最重要、一-次→一次、，-追→，追）
- [x] 清洗流水线工具 `scripts/clean_linebreaks.py` + `docs/clean-linebreaks-*.md` 审查稿
- [ ] **待办（本仓库整理任务覆盖）**：提交并打 tag `v1.0.3`
- [ ] 补 `docs/clean-linebreaks-review-mech.md` 走与 rules 一致的形式化审查
- [ ] 剩余"数字/标点误插"类噪音（`图1.00` / `后场.记录台` / `中，央裁判`）单列一轮

## 三、协作约定
- 迭代以**版本号**驱动；每个版本一个 Milestone + 至少一个 PR。
- 数据文件（`data/*.js`）改动必须走 PR + `node check.js`，禁止破坏结构。
- 发布前改 `config.js` 的 `APP_VERSION` 为单一可信源。
- 详细分支 / 提交 / 发布流程见 [GIT_WORKFLOW.md](GIT_WORKFLOW.md)。
